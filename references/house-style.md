# Minimal Analyst Deck — Presentation Style Guide

## 1. Purpose

This style guide defines how presentations should be polished and edited.

The target style is:

- minimal
- analytical
- professional
- human-made
- understated
- suitable for data analysis, product analysis, game analytics, business reviews, interview cases, and internal reporting

The goal is not to create a visually flashy presentation.

The goal is to make an existing presentation clearer, more consistent, more readable, and more professional.

The final deck should look like it was made by a thoughtful data analyst or strategy professional, not by an AI presentation generator.

---

# 2. Core Editing Principle

## Refine, do not reinvent

Preserve the author's original analytical structure unless there is a clear readability or communication problem.

Do not redesign slides simply to make them look more "creative" or "modern".

Do not introduce new visual concepts unless they improve comprehension.

Prioritize:

1. analytical clarity
2. visual hierarchy
3. consistency
4. readability
5. accuracy
6. aesthetics

Decoration is lower priority than communication.

---

# 3. Visual Identity

## Overall style

Use a restrained, editorial, analytical visual language.

The presentation should feel closer to:

- internal product review
- consulting analysis
- investment / strategy presentation
- research summary
- game analytics report

It should not feel like:

- marketing campaign
- startup pitch template
- AI-generated presentation
- Canva-style presentation
- social media infographic
- futuristic technology deck

---

# 4. Color System

## Background

Primary background:

`#F7F6F2`

This should be the default slide background.

Alternative section background:

`#EFEDE7`

Use only for section divider slides or very occasional visual separation.

Avoid pure white `#FFFFFF` as the dominant background unless required by an existing corporate template.

---

## Text colors

Primary text:

`#242424`

Secondary text:

`#686868`

Muted text / notes:

`#8A8A86`

Do not use pure black `#000000` as the dominant text color unless necessary.

---

## Lines and separators

Divider:

`#D9D7D1`

Chart gridline:

`#E4E2DC`

Table separator:

`#D9D7D1`

Use thin, subtle lines.

Avoid heavy borders.

---

## Accent color

Default accent:

`#385A64`

Use the accent color sparingly.

The accent color should indicate:

- the main series
- the primary conclusion
- the most important number
- the selected group
- the key comparison

Do not use the accent color decoratively.

---

## Comparison colors

Primary / focus:

`#385A64`

Comparison:

`#A8A8A3`

Other / background series:

`#D3D2CD`

Negative / warning only when analytically necessary:

`#A45B55`

Positive only when analytically necessary:

`#58705F`

Do not use red and green simply because something is "bad" or "good".

Use them only when the semantic meaning is genuinely useful.

---

# 5. Color Rules

Use no more than:

- one primary accent color
- one semantic warning color if necessary
- neutral gray tones

Avoid:

- rainbow palettes
- bright saturated blue
- neon colors
- gradients
- multiple accent colors on the same slide
- colorful charts without analytical reason

Default philosophy:

One thing is emphasized.
Everything else is visually quieter.

---

# 6. Typography

## Default font

English and numbers:

`Aptos`

Chinese:

`Microsoft YaHei`
or
`DengXian`

If an existing presentation already uses a strong professional font consistently, preserve it.

---

## Title size

Slide title:

26–30 pt

Weight:

Semibold

Avoid oversized titles.

Do not use:

40 pt+
unless the slide is a cover or section divider.

---

## Body text

Body:

14–16 pt

Secondary body:

12–14 pt

Chart labels:

11–13 pt

Footnotes / source:

9–10 pt

---

## Typography rules

Use sentence case.

Prefer:

`Tutorial completion improved after the FTUE change`

Avoid:

`TUTORIAL COMPLETION IMPROVED AFTER THE FTUE CHANGE`

Avoid excessive bolding.

Bold only:

- key numbers
- critical words
- primary conclusion fragments

Do not bold entire paragraphs.

---

# 7. Slide Margins and Alignment

Maintain consistent outer margins.

Recommended:

Left / right margin:

0.55–0.75 inch

Top margin:

0.4–0.6 inch

Bottom margin:

0.35–0.55 inch

Use consistent alignment across the full deck.

Prefer left alignment.

Avoid centered text except for:

- cover pages
- section divider pages
- occasional single-message slides

---

# 8. Title Philosophy

Prefer conclusion-driven titles.

A slide title should ideally communicate the main analytical message.

Bad:

`D1 Retention`

Better:

`Tutorial completers retain better on D1`

Bad:

`FTUE Performance`

Better:

`Naming remains the largest early FTUE drop-off`

Bad:

`Campaign Performance`

Better:

`Lower tCPI spend reduced installs while high-value acquisition remained stable`

Do not invent conclusions.

If the evidence is insufficient, keep the title descriptive and neutral.

Accuracy is more important than sounding insightful.

---

# 9. Recommended Slide Types

Use a limited number of repeatable layouts.

Professionalism comes from consistency.

---

## A. Conclusion + Main Chart

Structure:

- action title
- main chart
- 1–3 short observations
- source / definition

Use when one chart carries the argument.

---

## B. Two-Chart Comparison

Structure:

- action title
- chart A
- chart B
- one short interpretation under each
- one overall conclusion if needed

Use for:

- country comparison
- segment comparison
- before / after
- experiment / control

---

## C. Chart + Commentary

Structure:

- action title
- large chart on left or top
- 2–4 concise observations
- optional business implication

Use when the chart requires interpretation.

---

## D. Table / Breakdown

Structure:

- action title
- clean table
- one highlighted row or column
- short takeaway

Do not decorate the table.

---

## E. Executive Summary

Structure:

- title
- 3–5 findings
- each finding 1–2 lines
- optional number prefix: 01 / 02 / 03

Do not place findings inside decorative cards.

---

## F. Section Divider

Structure:

- section number
- short section title
- optional one-line framing statement

Use sparingly.

Keep visually quiet.

---

## G. Process / Funnel

Use simple arrows, lines, or labeled stages.

Avoid illustrated journey maps unless genuinely necessary.

---

## H. Experiment Slide

Recommended structure:

- hypothesis
- test design
- primary KPI
- result
- interpretation

Prefer a simple analytical layout over a "framework" graphic.

---

# 10. Chart Design

Charts are analytical objects, not decoration.

---

## General rules

Prefer:

- bar charts
- line charts
- dot plots
- slope charts
- scatter plots
- simple stacked bars
- clean tables

Use pie / donut charts only when composition is extremely simple.

Avoid:

- 3D charts
- gauges
- radar charts
- ornamental infographics
- decorative pictograms

---

## Highlight logic

Use:

Primary series:
`#385A64`

Comparison:
`#A8A8A3`

Other:
`#D3D2CD`

Highlight only what matters.

---

## Gridlines

Remove unnecessary gridlines.

If gridlines help:

- use light gray
- use thin lines
- avoid visual dominance

---

## Legends

Remove legends when direct labeling is clearer.

Prefer direct labels where practical.

---

## Data labels

Show only analytically useful labels.

Do not label every point automatically.

---

## Decimal precision

Use appropriate precision.

Examples:

Prefer:

`58.7%`

instead of:

`58.65%`

Prefer:

`€1.2M`

instead of:

`€1,234,567`

unless exact precision matters.

---

## Axes

Do not distort axes to exaggerate differences.

Bar charts should generally start at zero.

Line charts may use tighter ranges when analytically justified.

---

# 11. Table Design

Tables should be functional.

Use:

- subtle row separators
- minimal fill colors
- one highlighted row / column
- aligned decimals
- consistent number formats

Avoid:

- full borders around every cell
- strong header fills
- alternating rainbow rows
- excessive bold text

Use light shading only when it improves scanning.

---

# 12. KPI Presentation

Avoid default AI KPI cards.

Do not automatically create:

[ KPI ]
[ KPI ]
[ KPI ]

inside rounded boxes.

Instead prefer:

`D1 Retention`
`43.2%`

with simple alignment and supporting context.

If multiple KPIs are shown:

- use consistent spacing
- use typography rather than boxes
- use thin separators if needed

---

# 13. Whitespace

Use whitespace deliberately.

Whitespace should improve hierarchy and readability.

However:

Minimal does not mean sparse.

Do not remove useful analytical information just to create a "clean" look.

A data analysis slide may contain:

- one chart
- one table
- several labels
- 2–4 observations
- metric definitions

if the information is necessary.

The goal is low visual noise, not low information density.

---

# 14. Text Density

Avoid long paragraphs.

Convert long text into:

- short bullets
- direct statements
- chart annotations
- brief conclusions

Recommended bullet length:

1–2 lines.

Recommended number of bullets:

2–5.

Do not use bullets when one short paragraph is clearer.

---

# 15. Annotation Style

Use annotations to explain:

- important changes
- unusual peaks
- experiment dates
- launch dates
- outliers
- structural breaks

Use small labels and subtle leader lines.

Avoid comic-style callouts.

---

# 16. Numbers

Numbers should be visually easy to scan.

Use:

- consistent decimal places
- aligned units
- clear percentage formatting
- shortened large values where appropriate

Examples:

`€1.4M`

`32.4%`

`+2.1pp`

`-14%`

Use percentage points (`pp`) when comparing percentage-rate differences.

---

# 17. Footnotes and Definitions

Analytical slides should include definitions when needed.

Examples:

`D1 = active on the calendar day after install`

`Population = active players only`

`Source: AppsFlyer + internal game data`

Footnotes should be visually quiet.

Use 9–10 pt muted text.

---

# 18. Source Style

Preferred:

`Source: Internal data, AppsFlyer`

or

`Source: Internal event data, May–Jun 2026`

Avoid large "SOURCE" labels.

---

# 19. Images

Use images only when they contribute analytical or contextual value.

Examples:

- game screenshots
- UI screenshots
- experiment variant screenshots
- product screenshots

Do not use generic stock imagery.

Do not generate decorative AI images unless explicitly requested.

---

# 20. Icons

Default: do not use icons.

Use icons only when they have a clear navigational or semantic role.

Never use emojis.

Avoid decorative icon rows.

---

# 21. Shapes

Use simple shapes.

Allowed:

- rectangles
- lines
- circles
- arrows

Prefer square or very slightly rounded corners.

Avoid exaggerated rounded cards.

Avoid excessive shadow.

---

# 22. Shadows and Effects

Default:

No shadows.

If a shadow is necessary:

- extremely subtle
- low opacity
- small blur

Avoid:

- glow
- bevel
- 3D effects
- glass effects
- transparency-heavy effects

---

# 23. What to Avoid

Never add these unless explicitly requested:

- gradients
- glassmorphism
- neon colors
- emoji
- decorative illustrations
- generic AI imagery
- floating cards
- excessive rounded rectangles
- huge KPI numbers without context
- inspirational quotes
- fake quotes
- fake customer statements
- futuristic UI
- glowing elements
- unnecessary icons
- large decorative circles
- random abstract shapes
- startup-style marketing slogans
- rainbow charts
- clip art

---

# 24. Anti-AI Rules

The deck should not look machine-generated.

Avoid common AI presentation patterns:

- three identical cards
- oversized numbers
- icon + headline + paragraph repetition
- generic "Key Insights" pages
- overly symmetrical layouts
- artificial inspirational text
- decorative gradients
- meaningless visual metaphors
- excessive section labeling
- repeated card grids

Prefer small imperfections in layout over generic template repetition if the result feels more natural.

Human analytical structure is more important than perfect visual symmetry.

---

# 25. Editing Existing Slides

When polishing an existing presentation:

Do:

- fix alignment
- fix spacing
- standardize font sizes
- simplify color usage
- improve chart readability
- rewrite weak titles
- shorten verbose text
- normalize number formatting
- reduce clutter
- align objects
- improve visual hierarchy
- fix inconsistent margins

Do not:

- change the analytical meaning
- invent new conclusions
- add unsupported claims
- add decorative content
- replace simple charts with unnecessary infographics
- remove useful information purely for aesthetics
- restructure the whole slide without a clear reason

---

# 26. Preserve Author Intent

Assume the author chose the slide content intentionally.

The editing task is to improve the presentation, not replace the author's thinking.

If a slide is analytically sound but visually rough:

Polish it.

Do not redesign it from scratch.

---

# 27. Content Editing Rules

Improve wording for:

- clarity
- brevity
- analytical tone
- precision

Avoid:

- corporate buzzwords
- vague claims
- exaggerated language

Avoid phrases such as:

- game-changing
- revolutionary
- transformative
- exciting opportunity
- unlocking value
- powerful insights
- driving excellence

Prefer plain language.

---

# 28. Analytical Tone

Preferred tone:

- factual
- concise
- direct
- evidence-based
- neutral

Example:

Bad:

`The new tutorial delivered an amazing improvement in player engagement.`

Better:

`D1 retention increased by 2pp after the tutorial change.`

---

# 29. Business Implication

When useful, separate:

Observation

from

Interpretation

from

Action

Example:

Observation:
`Skip players retain 14pp worse on D1.`

Interpretation:
`Skipping may disproportionately affect players who still need onboarding support.`

Action:
`Test a shorter tutorial path rather than a full skip.`

Do not present interpretation as fact unless supported.

---

# 30. Slide Order

For analytical decks, prefer:

1. context / question
2. executive summary
3. evidence
4. segmentation
5. diagnosis
6. recommendation
7. next steps

Not every deck needs all sections.

---

# 31. Cover Slide

Keep covers minimal.

Recommended:

Title

Subtitle or date

Author / team

Avoid:

- full-page stock photography
- abstract AI art
- decorative graphics

Background may be:

`#F7F6F2`

or a muted dark section background if appropriate.

---

# 32. Executive Summary

Executive summary should contain real conclusions.

Do not use generic labels such as:

`Key Insights`

unless useful.

Prefer:

`Three findings explain the retention gap`

Then list findings.

---

# 33. Section Divider

Use:

Section number

Title

Optional one-sentence framing

Example:

`02`

`Where players drop during onboarding`

Do not add decorative artwork.

---

# 34. Final Slide

Preferred:

`Next steps`

or

`Discussion`

Avoid:

`THANK YOU`

unless presentation context requires it.

---

# 35. Speaker Notes

Speaker notes should:

- explain interpretation
- contain caveats
- include context not needed visually
- help the presenter remember the story

Do not duplicate the slide word-for-word.

---

# 36. Accessibility

Ensure:

- readable font sizes
- sufficient contrast
- clear hierarchy
- charts understandable without relying only on color
- labels are legible

---

# 37. Quality Control Before Export

Before finalizing the presentation, check:

## Consistency

- same background
- same title size
- same margins
- same font family
- same chart palette
- same number formatting

## Alignment

- titles aligned
- charts aligned
- text blocks aligned
- consistent vertical spacing

## Charts

- no unnecessary legends
- no excessive decimals
- no rainbow palette
- primary comparison is visually clear

## Text

- no long paragraphs
- no unsupported claims
- no filler language
- titles communicate conclusions where appropriate

## Visual style

- no gradients
- no emojis
- no decorative icons
- no excessive cards
- no AI-looking visual gimmicks

---

# 38. Editing Priority

When multiple improvements are possible, prioritize in this order:

1. factual accuracy
2. analytical clarity
3. title quality
4. chart readability
5. visual hierarchy
6. alignment
7. spacing
8. typography consistency
9. aesthetics

Never sacrifice accuracy for aesthetics.

---

# 39. Final Instruction to the AI Editor

When editing a presentation:

Read this style guide before making changes.

If there is any conflict between this file and the default behavior of a PPT skill, follow this file.

Preserve the author's analytical thinking.

Polish the presentation rather than redesigning it.

Do not introduce visual elements simply to make the slide appear more sophisticated.

The final output should feel:

calm,
precise,
analytical,
professional,
and human-made.
